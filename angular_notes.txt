        -> when it is active, it will listen any event throughout your application.
        -> when you want modify the property after getting input values then we will use.
        -> Only works when we have input property
        -> try to avoid as much as possible
    2. ngOninit
    3. ngDoCheck
        -> never use docheck and ngOnChanges in same component, both do same thing

    4 ngAfterContentInit
        -> Content projection
            -> one of important topic, if you want header on the top, footer on the bottom and side bar on left side,

                -> used to display the content whatever is written

                -> used to acces the data of ng-content components

    -> rxjs, observables and streams
        -> rxjs use concept of whatever the data we getting is stream of data
        -> netflix, hotstar, amazon prime, youtube are straming services.
        -> if you want that stream , you must subscribe to it, similar concept is used in rxjs.
        -> we have two type of architectures
            1. pull based architecture
                -> if we want add the newdata to the data, you need to get the data first
                    then you need to add the newdata and call the get data again to display.
                -> getData ==> addDate ==> getData
            2. push based architecture
                -> if we want to add the newdata to the data , we can add the newdata directly to the data,
                    no need to call the get data again
                -> getData ==> continous stream of data ==> addData
        -> Rxjs internally uses push based architecture.
        -> RxJs is an library for writing reactive propgramming.
        -> observables are stream of data which we can subscribe.
        -> we can create observables by using both http and rxjs.
            ->  stream = new Observable(observer => { observer.next('user2'); });
            -> if we want the data in the stream, you need to subscribe to it.
            -> for every next, the subscribtion calls everytime, so it is simply continous stream of data.
        -> request api is more powerful than http api. it has more features
    -> http methods
        -> get, post, put, delete
    -> rxjs operators
        -> we have more than 100 operators.
        -> why we need rxjs operators ?
            -> RxJs gives stream of data and that stream of data cannot be modified after subscribe.
            -> the stream can modify inside the `pipe` function.
        -> ShareReplay
            -> when api's called more than once in single component, we have performance issues. we will cache the request
                by using this operator , so we can use this data.
            -> getRooms$ = this.http.get<RoomsList []>('/api/rooms').pipe(shareReplay(1));
                -> getRoom$ is property
                -> we will caching the every request of get api `/api/rooms/`.
        -> Async pipe
            -> when we subscribe many streams, we must unsubscribe the streams. if not performance issues will come.
            -> whenever ngOnDestroy calls, async pipe will aslo unsubscribing that object.
            -> async pipe can also return null.
            -> if we use multiple times then it subscribes multiple times
            -> async pipe has to subscribe multiple times, so we can use below line
                -> async as rooms
            -> use async pipe as much as possible.
        -> CatchError
            -> we can handle 404 exceptions by using async
            -> by using ngrx also we can handle.
            -> we can't modify the data, after we subscribing, but we can do it by using pipe
                -> we can display the particular error message by using pipe operator.
            -> we can also display the by using subject, it uses both Observable and observer
            -> subject is base class for different streams which we get. Internally angular also subject at lot of places.
                -> error$ = new Subject<string>(); , used to create an subject.
                -> getError$ = this.error$.asObservable(); , make it as active stream to listen the data.
                -> error$.next(err), push the error to the stream.
                -> Don't use this in component. do it in service. by using component interaction through services.
        -> Map Operators
            -> we can modify the stream by using the map operator by subscribing to the same stream.

-> Http Interceptors and APP_INITIALIZERS
    -> Allow us to intercept request.
    -> we can change the data and headers
    -> APP_INITIALIZERS allows you to inject function as application startup.
    -> when we add headers to every request, it's like duplicating code, so to resolve this issue, there is
        concept called interceptors.
    -> when we send request from client to server and get response from server, there is
        mediator , it will listen everything is called interceptor.
    -> we can common headers inside the interceptor, if we want to add date and timestamp to each and every request we can do that,
        we can handle the token expire case.
    -> to generate interceptor
        -> ng g interceptor <name>
    -> http interceptor can modify our request and response both
    -> this line send request to our server
        -> return next.handle(request);
    -> HTTP_INTERCEPTORS is injection token.
    -> angular has some interceptors , thar are executed sequentially, follows FIFO principle.
    -> when we add extra interceptors in app.module then it will be added to the queue.
    -> you cannot modify the request directly, you need to clone it and send the new request instead of old one.
    -> in routing and forms we can majorly modify the response.
    -> APP_INITIALIZER is a service, which is used to load the data before our app gets initialised.
    -> when we some configuration and need to load that configuration before our app is initialised and save that data into service,
        then we can use it.
    -> APP_INITIALIZER can plugin our service and call that service, before our app is initialised.
        we can do anything whatever we want into that service, we can load the config file.

    -> Setup Router
        -> Import Routermodule
        -> forRoot method allows us to add multiple route config
            -> it it singleton instance , you should not forRoot multiple times.
        -> to configure route , you need two things
            -> 1. path : it is string value, whatever you added that will be added to the parent route
            -> 2. component : when we go that url, which component i need to load.
        -> <router-outlet></router-outlet>
            -> it will give the content in that single commponent only.
            -> what ever the path matches, it loads that respective component.
            ->
        -> default route
            -> { path : '',redirectTo : '/rooms' , pathMatch : 'full' }
            -> we can also regexp in case of path.
        -> <a [href]="'rooms'">Rooms</a>
            -> don't use href, because it loads the entire page. angular is SPA not MPA
            -> so use [routerLink] instaead of href
        -> <a [routerLink]="'rooms'">Rooms</a>
            -> it doesn't loads the entire page when routing.
        -> ng add @angular/material
            -> used to add angular material.
        -> ng generate @angular/material:navigation <component-name>
            -> used to create navigation component.
        -> dynamic route
            -> room/:id is example of dynamic route.
            -> [routerLink]="['/rooms',room.roomNumber]
                -> / beofore the rooms will be append the /rooms to the localhost:8092,
                -> while without / , the rout will be append to initial route like below
                    -> http://localhost:8092/rooms/rooms/2 , then page not found error will be occured.
        -> wild card route
            -> { path : '**', component : NotfoundComponent }
            -> incase of page not found, we can use this wildcard route.
    -> Using ActivatedRoute service
        -> private router : ActivatedRoute
        -> it allows you to read the router data.
        -> allows access to snapshot params
        -> allows to access data from route config.
        -> this.router.params.subscribe((params) => {}), will listen to live changes and modify the data accordingly.
            -> while we talking rxjs, we should not subscribe, because it will lead to the memory leakage.
            -> we can avoid subscription by using rxjs operators. by using .pipe and map we can.
                -> this.id$ = this.router.params.pipe(map(params => params['roomId']));
        -> we can also use snapshot params
            -> let params = this.router.snapshot.params;
                -> it doesn't listen to the live changes., so we can avoid this.
        -> if we have multiple values , then there will problem with params. so we must use paramMap.
            -> id$ = this.router.paramMap.pipe( map((params) => params.get('roomId')));
